## 晚高峰拥塞测试与延迟抖动分析

在夜间高峰时段（20:00-23:00），公网国际出境链路丢包率飙升，TCP 拥塞控制算法（如 Cubic）因丢包误判将发送窗口腰斩，导致 带宽与流量消耗模型 / 晚高峰国际网关 QoS 穿透 发生卡顿：

```text
[RTT 波动测试对照]
目标接口: 带宽与流量消耗模型 / 晚高峰国际网关 QoS 穿透
公网直连链路: ───35ms───190ms───(丢包)───350ms───(断流: 晚高峰持续丢包 (> 25%) / 4K 播放降码至 480p / 流量包极速消耗超标)
内网 IPLC 专线: ───22ms───22ms───23ms───22ms───23ms───(达标: < 0.2% (物理专线零丢包))
```

时延抖动与微丢包是造成业务中断的元凶，高稳定性环境必须锁定物理专线。
