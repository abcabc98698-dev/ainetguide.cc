# 会议掉线排查：晚高峰拥塞对抗与 QoS 限速穿透策略

## 晚高峰拥塞测试与延迟抖动分析

在夜间高峰时段（20:00-23:00），公网国际出境链路丢包率飙升，TCP 拥塞控制算法（如 Cubic）因丢包误判将发送窗口腰斩，导致 Zoom / Microsoft Teams 跨国商务会议 发生卡顿：

```text
[RTT 波动测试对照]
目标接口: Zoom / Microsoft Teams 跨国商务会议
公网直连链路: ───35ms───190ms───(丢包)───350ms───(断流: Zoom Error 5003 / 语音断续杂音 / 共享屏幕严重丢帧卡死)
内网 IPLC 专线: ───22ms───22ms───23ms───22ms───23ms───(达标: < 2.5ms (无感通信))
```

时延抖动与微丢包是造成业务中断的元凶，高稳定性环境必须锁定物理专线。

## 拥塞排障问答

### Q: 开跨国视频会议时经常对方说听不清我的声音、声音断断续续？
实时音频走 UDP 协议，普通公网代理优先保障 TCP 而丢弃 UDP。需配置专线通道并开启客户端 UDP 优先加速策略。
